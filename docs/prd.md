## 一、产品概述

### 1.1 产品定位

**一镜一梳（明镜）** 是以东方本体论（阴阳五行、三才八卦）为核心框架的曼陀罗疗愈 AI 工作台，**服务疗愈师单端**——为疗愈师提供高效的解读报告生成工具，以及辅助理解报告、准备来访者应答的问答助手。来访者不直接接触产品，其交付物为疗愈师导出的 PDF 解读报告。

**一句话定位**：曼陀罗疗愈 AI 工作台——解读报告生成 + 报告问答助手（疗愈师端）

**MVP 形态**（D-106）：单用户本地工具——无多租户、无前端，CLI/本地 API 交互，报告与问答产物落盘为本地文件；给合作疗愈师试用走单租户私有部署，为远期选项。

### 1.2 目标用户

| 用户角色 | 描述 | 核心诉求 | 服务方式 |
|---|---|---|---|
| **曼陀罗疗愈师**（核心用户） | 个人执业或小型工作室的曼陀罗疗愈师，有专业基础但时间精力有限 | 节省解读时间、提升解读质量、标准化报告输出、减少重复性答疑 | 本地工具（CLI / 本地 API） |
| **新手疗愈师**（扩展用户） | 正在学习曼陀罗解读，缺乏实战经验 | 学习解读方法、获得标准化框架、模拟练习 | 本地工具（CLI / 本地 API） |

> **MVP 阶段单端**：疗愈师端做报告生成 + 问答助手 + PDF 导出交付；来访者不接触产品。

### 1.3 产品边界

**做什么**：
- 曼陀罗绘画解读报告的 AI 辅助生成（疗愈师端）
- 基于解读报告的问答助手（辅助疗愈师理解报告、准备来访者应答）
- 结构化的解读框架和质量保证体系

**不做什么**：
- 不替代疗愈师做最终判断（AI 是辅助，不是疗愈师）
- 不做医学/心理疾病诊断（只做能量层面的参考）
- 不做实时对话式疗愈（MVP 阶段仅报告范围内问答）
- 不做多流派（MVP 只做曼陀罗一个流派）

### 1.5 商业假设

| 要素 | 设定 |
|---|---|
| 付费方 | **疗愈师**（小 B / 一人公司），订阅或实例费定价，API 成本计入定价由疗愈师承担 |
| 交付形式 | 按 **FDE 业务**推广；因目标客户是个人疗愈师/一人公司，采用"**产品 + 轻陪跑**"交付——产品自助使用 + 轻量陪跑服务（上手引导、解读质量校准、案例复盘） |
| 来访者侧 | 不直接接触产品，交付物为 PDF 报告；解读沟通发生在产品外（微信等），无来访者端成本 |
| 边界 | "轻陪跑"不含代解读、不含长期代运营；深度服务另行约定 |

### 1.4 演进方向

| 方向 | 内容 | 规划 |
|---|---|---|
| 问答能力深化 | 报告范围内问答质量提升：来源标注、推理链展示、多报告关联问答 | v1.x |
| 疗愈师工作流 | 个案管理（多报告对比、长期跟踪）、实时话术辅助、个案模拟练习 | v1.0 起 |
| 获客支持 | 内容流水线（朋友圈/小红书素材）、课程开发辅助 | v1.0 起 |
| 个性化生成 | 疗愈师个人知识库（Agent 自动记忆：报告修改沉淀为个人记忆，反哺针对该疗愈师的报告生成；非疗愈师手动维护） | v1.x |

> 明确不做：面向来访者的 AI 疗愈对话 / to C 自助产品形态。来访者侧的解读沟通由疗愈师通过既有渠道（微信等）完成。

## 二、用户旅程与核心场景

### 2.1 疗愈师核心旅程

```
获取来访者曼陀罗绘画
 ↓
登录工作台，上传画作 + 填写基本信息
 ↓
AI 生成解读报告（3分钟内）
 ↓
疗愈师审核、修改、确认报告
 ↓
导出 PDF 报告
 ↓
将 PDF 交付来访者（微信等渠道）
 ↓
（可选）用问答助手做解读准备 / 应答准备
 （自己没看懂的地方先问透；
 来访者提问拿不准时先辅助作答）
 ↓
（可选）将报告归档到个案档案
```

### 2.2 来访者侧交互（产品外）

来访者不登录、不接触任何产品界面：

```
收到疗愈师发来的 PDF 解读报告
 ↓
阅读报告（措辞友好，专业术语如"水多火灭"在文内即有解释）
 ↓
有疑问 → 微信询问疗愈师
 ↓
疗愈师（必要时借助问答助手辅助）回应
```

> 来访者对报告的疑问、反馈，是疗愈师使用问答助手"应答准备"场景的真实输入来源。

### 2.3 MVP 核心场景

| 场景编号 | 场景名称 | 角色 | 优先级 | 对应工作流 |
|---|---|---|---|---|
| S-001 | 生成曼陀罗解读报告 | 疗愈师 | P0 | WF-REPORT-GEN |
| S-002 | 疗愈师用问答做解读准备 | 疗愈师 | P0 | WF-REPORT-QA（疗愈师模式） |
| S-003 | 疗愈师借助问答助手准备来访者应答 | 疗愈师 | P0 | WF-REPORT-QA（应答准备场景） |
| S-004 | 疗愈师导出 PDF 报告交付来访者 | 疗愈师 | P0 | 报告导出 |

### 3.2 MVP 功能清单

#### 功能模块 1：解读报告生成（P0 · 疗愈师端）

**功能描述**：疗愈师上传曼陀罗绘画（或输入关键信息），AI 基于东方本体论框架和曼陀罗解读体系，生成结构化的解读报告。

**子功能**：

| 子功能 | 描述 | 优先级 |
|---|---|---|
| 输入采集 | 支持上传曼陀罗图片、填写来访者主题、基本信息、绘画背景 | P0 |
| 三圈划分 | 自动或手动划分曼陀罗的内圈/中圈/外圈 | P0 |
| 符号识别 | 识别画面中的颜色、形状、结构、位置等关键符号 | P1（MVP 可手动输入） |
| 五行解读 | 分析五行能量分布、生克乘侮关系 | P0 |
| 议题定位 | 由来访者输入主题确定议题领域（宫位读取为预留能力） | P0 |
| 报告生成 | 按标准模板生成 8 章节结构化解读报告 | P0 |
| 报告编辑 | 报告以 Markdown 落盘，疗愈师本地编辑后重新渲染 | P0 |
| 报告导出 | 导出 PDF（交付来访者的标准形式）/ Markdown | P0 |
| 报告版本管理 | 保存报告的不同版本，支持对比和回溯 | P1 |

**报告结构（标准版）**：
1. 整体画面直觉
2. 主题确认与解读重点
3. 三圈结构解读
4. 五行能量总览
5. 议题分布
6. 核心议题深挖
7. 生机与转化方向
8. 调理建议（清理/调理/显化）

> 详细设计见：`specs/WF-REPORT-GEN.md`

#### 功能模块 2：报告问答助手（P0 · 疗愈师端）

**功能描述**：针对已生成的解读报告，疗愈师可以进行深度问答。AI 在报告基础上提供延伸解读，服务疗愈师的两个真实场景：
1. **解读参谋**：疗愈师自己对报告有疑问——某个结论怎么看出来的、根因是什么、两幅画的报告哪里矛盾了——先问透，再面对来访者
2. **应答准备**：来访者就报告提问、疗愈师拿不准时，借助问答助手组织专业回应

**使用场景**：

| 维度 | 场景一：解读参谋 | 场景二：应答准备 |
|---|---|---|
| 触发时机 | 生成报告后、交付前 | 交付后，来访者提问时 |
| 核心目标 | 帮疗愈师想透报告 | 帮疗愈师组织给来访者的回应 |
| 语言风格 | 专业、精准、有深度 | 专业 + 可转述（疗愈师可消化后用自己的话告诉来访者） |
| 回答深度 | 深（根因层 + 核心层 + 表现层） | 中（核心层 + 表现层，避免过度解读） |
| 知识库范围 | 全部知识单元 | 全部知识单元 |

**子功能**：

| 子功能 | 描述 | 优先级 |
|---|---|---|
| 报告加载 | 加载指定解读报告作为问答上下文 | P0 |
| 问题分类 | 自动识别问题类型（5类） | P0 |
| 报告定位 | 定位问题涉及的报告章节和结论 | P0 |
| 本体论关联 | 关联到相关的本体论状态和关系 | P0 |
| 知识库补充 | 补充报告中未展开的相关内容 | P0 |
| 答案生成 | 基于报告 + 本体论 + 知识库生成回答 | P0 |
| 多轮对话 | 支持多轮追问和深入探讨 | P0 |
| 来源标注 | 回答中标注信息来源 | P1 |
| 边界提示 | 超出报告范围的内容明确标注 | P0 |
| 输出安全审核 | 医学诊断类、承诺类、绝对化等审核 | P0 |
| 危机干预话术 | 检测到危机信号时触发 | P0 |

**问答类型**：
1. **细节追问**：对报告中某个结论追问"为什么"、"怎么看出来的"
2. **深度探讨**：围绕某个议题深入展开，探讨更多可能性
3. **视角切换**：从不同视角（能量/心理）解读同一问题
4. **方案细化**：针对调理建议，细化具体的操作方法和步骤
5. **跨议题关联**：探讨报告中不同议题之间的关联和影响路径

> 详细设计见：`specs/WF-REPORT-QA.md`

## 四、核心功能需求详述

### 4.1 解读报告生成

#### 4.1.1 输入要求

**必填项**：
- 曼陀罗图片（或手动输入的关键信息）
- 来访者主题（本次绘画想要探索的问题）

**可选项**：
- 来访者基本信息（性别、年龄、职业等）
- 绘画背景（绘画时的状态、之前是否画过等）
- 报告版本选择（标准版/精简版/深度版，MVP 只做标准版）
- 三圈标记图（如疗愈师已标注好，可直接使用）

#### 4.1.2 生成要求

- **速度**：单份报告生成时间 < 3 分钟
- **完整性**：覆盖 8 个标准章节，无缺章
- **一致性**：同一幅画多次生成，核心结论一致性 > 80%
- **证据链**：主要结论 100% 有画面证据支撑
- **深度**：至少触及 1-2 个根因层状态
- **安全性**：0 条越界内容（不做医学/心理诊断、不做财务承诺）
- **单版本措辞友好**：只生成一份报告；保留专业术语（如"水多火灭"）并在文内直接给出解释——既显得专业，来访者也读得懂

#### 4.1.3 输出要求

- **格式**：Markdown + YAML 元数据
- **结构**：严格按照 8 章节标准结构
- **可编辑**：生成后可由疗愈师自由编辑修改
- **可追溯**：元数据记录生成时间、输入信息、核心状态等
- **可导出**：一键导出 PDF（交付来访者的标准形式）

### 4.2 报告问答（疗愈师端）

#### 4.2.1 场景一：解读参谋

- 更专业的术语和分析深度
- 支持完整的推理链条展示
- 可查看报告的生成逻辑和证据链
- 支持疗愈方案的细化探讨
- 支持多视角对比分析（能量视角 vs 心理视角）

#### 4.2.2 场景二：应答准备

- 围绕来访者的实际提问组织回应素材
- 回答可直接被疗愈师消化后转述（不替代疗愈师自己的专业判断）
- 避免过度解读：给可能性，不给定论
- 明确边界提醒："能量层面的参考，不是诊断"——回应来访者时的口径提示

#### 4.2.3 质量要求

| 指标 | 目标 |
|---|---|
| 锚定报告 | >90% 回答有报告依据 |
| 回答相关性 | >85% 与问题直接相关 |
| 专业深度 | ≥ 4.0 分（1-5 分制，口径见 ACCEPTANCE §6.1 M-030） |
| 边界清晰 | 100% 超范围有标注 |
| 安全越界 | 0 条严重越界 |

## 五、非功能需求

### 5.1 性能需求

| 指标 | 目标 |
|---|---|
| 报告生成时间 | < 3 分钟/份 |
| 问答响应时间 | < 10 秒/轮 |
| 使用稳定性 | 连续 1 小时使用无崩溃（本地形态，无服务可用性指标） |

### 5.2 安全与隐私

> **部署形态基准**：单用户本地运行（D-106）——数据不出本机目录；个案化名建档与 LLM 调用脱敏保留，单租户私有部署为远期选项。

| 要求 | 说明 |
|---|---|
| 部署形态 | 单用户本地运行：个案数据存本机目录，不经过任何服务端 |
| 数据脱敏 | 三层脱敏：① 输入侧——个案以化名/编号建档，系统不设真实姓名字段，画作上传前提示移除画面外可识别信息；② 存储侧——画作图像与个案文本分离目录存储（本地磁盘）；③ 模型侧——调用 LLM API 的 prompt/上下文不含真实身份标识，仅传化名、个案编号与脱敏后的画作描述 |
| 数据隔离 | 个案与个案之间以目录隔离；多疗愈师/多租户隔离为远期选项 |
| 数据归属 | 个案数据（画作、报告、问答记录）归疗愈师所有，平台不单独收集、不用于模型训练 |
| 操作审计 | 关键操作留痕，AI 生成内容标注来源 |
| 报告免责 | 每份报告明确标注"AI 辅助生成，仅供参考" |
| 安全护栏 | 四级内容分级（safe/reminder/caution/forbidden） |
| 危机干预 | 检测到自杀/自伤/严重心理疾病等边界情况有明确的转介机制；输入侧（主题/背景文字）命中危机信号时提示疗愈师注意个案风险（P3 转型） |

### 5.3 可扩展性

| 要求 | 说明 |
|---|---|
| 插件化架构 | 流派插件可插拔，新增流派不修改核心代码 |
| 框架可替换 | Agent 框架与业务逻辑解耦，可平滑升级 |
| 知识库可扩展 | 知识库分层设计，支持持续补充和迭代 |
| 工作流可配置 | 新增业务场景通过组装现有能力实现 |
| 单端架构 | 同一套知识体系专注服务疗愈师工作流，术语与交互无需多模式适配 |

### 5.4 易用性

| 要求 | 说明 |
|---|---|
| 疗愈师端开箱即用 | 无需技术背景，核心功能 30 分钟内上手 |
| 结果可控 | AI 生成的内容可编辑、可修改、可推翻 |
| 交互简洁 | CLI/文件操作聚焦核心功能，不堆砌选项 |
| 引导友好 | 首次使用有上手引导；问答助手有明确的能力边界说明 |

## 六、优先级排序

### 6.1 MVP 范围（P0）

必须完成，否则不构成 MVP：

1. **解读报告生成**（WF-REPORT-GEN）
 - 输入采集（图片 + 主题 + 基本信息）
 - 手动输入符号信息（MVP 简化方案）
 - 五行解读 + 议题定位（由来访者输入确定，九宫宫位读取为预留能力）
 - 8 章节标准报告生成
 - 报告编辑
 - 报告导出（PDF，交付来访者的标准形式）

2. **报告问答助手**（WF-REPORT-QA）
 - 报告加载与上下文管理
 - 5 类问题的问答能力
 - 解读参谋 + 应答准备两场景支持
 - 边界提示 + 免责声明
 - 输出安全审核 + 危机干预话术

3. **系统基础**
 - 报告管理（本地目录：索引、查看、搜索、删除、导出）

### 6.2 P1 功能（MVP 验证后优先做）

6. 问答历史保存与检索

4. 多流派接入（玛雅历等）

6. 多报告关联问答（跨个案对比）

## 七、成功指标

### 7.1 疗愈师端指标（确认口径）

> **指标口径治理**：数值以 ACCEPTANCE §6.1 指标字典（M-NNN）为唯一口径源，本节数值为同步副本。

| 指标 | 目标值 | 衡量方式 |
|---|---|---|
| 报告采纳率 | > 70% | 疗愈师自评"可用/只需微调"的比例 |
| 报告编辑率 | < 30%（越低越好） | 生成后改动字数占比，后台数据 |
| 问答辅助使用率 | > 60% 的报告生成后使用过问答助手 | 后台数据 |
| 交付完成率 | > 80% 的报告完成"生成 → 导出 PDF" | 后台数据 |
| 问答满意度 | ≥ 3.5 分（1-5 分制问卷） | 疗愈师问卷自评，计算方式见 ACCEPTANCE §6.1 M-064 |
| 使用频率 | 每周 ≥ 3 次/目标用户 | 后台使用数据 |
| 生成速度 | < 3 分钟/份 | 系统计时 |
| 核心结论一致性 | > 80% | 同图多次生成的对比测试 |
| 用户推荐意愿 | 愿意推荐给同行 | 用户访谈/NPS |

> 来访者侧体验无产品界面可测，通过疗愈师访谈间接收集（如"来访者看完报告后的反应"）。

### 7.3 质量指标

| 维度 | 目标 |
|---|---|
| 报告完整性 | 8 章完整，无缺章 |
| 证据链完整度 | 主要结论 100% 有画面证据 |
| 解读深度 | 至少触及 1-2 个根因层状态 |
| 建议可操作性 | 每条建议有具体做法 |
| 安全合规 | 0 条严重越界内容 |
