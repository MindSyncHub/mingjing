## 一、核心定位

本知识库不是普通的向量 RAG，而是**本体论驱动的结构化 RAG**。

区别于普通 RAG：
- **不是把文档切块丢进向量库**，而是按知识单元组织，每个单元有明确的类型、属性和关系
- **不是靠相似度找文字**，而是基于本体论骨架进行推理，推理链条可追溯
- **不是只有一种输出**，而是同一知识支持两种表达深度（解读参谋的专业版 / 应答准备的可转述版），知识本体只有一份（单版本口径）

## 二、四层 RAG 架构

```
┌─────────────────────────────────────────┐
│  生成层（Generation）                    │
│  硬结论规则引擎 + 软表达大模型            │
├─────────────────────────────────────────┤
│  推理层（Reasoning）                     │
│  状态因果链 / 五行乘侮 / 跨议题关联        │
├─────────────────────────────────────────┤
│  检索层（Retrieval）                     │
│  结构化召回 + 向量召回 + 关键词召回        │
├─────────────────────────────────────────┤
│  知识层（Knowledge）                     │
│  本体层 → 流派层 → 议题层 → 方案层 → 应用层 │
└─────────────────────────────────────────┘
```

### 3.2 知识单元结构

每个知识单元包含：

```yaml
id: wealth.self_worth.low_deservingness
type: issue_clause
layer: L3
topic: 财富关系
state_id: S-001  # 关联本体论状态 ID
version: 0.1.0
status: case_verified  # ai_draft / source_supported_draft / case_verified / reviewed
relay_risk: low           # 转述风险分级（low/medium/high）——应答准备场景输出可能被转述给来访者

# 双内容
content_professional:  # 专业版（疗愈师模式）
  definition: "..."
  psychological_correspondence: "..."
  energy_analysis: "..."
  clinical_evidence: "..."

content_lay:     # 通俗解释（应答准备/报告引用，文内解释专业术语）
  plain_explanation: "..."
  common_manifestation: "..."
  gentle_reflection: "..."

# 元数据
tags: [财富, 配得感, 金行]
related_states: [S-017, S-009, S-003]
related_interventions: [I-001, I-005, I-012]
risk_level: safe  # safe / reminder / caution / forbidden
source_ref:
  - "20-疗愈体系/10-议题层/01-财富关系.md"
 - "case-003" # 案例级来源标注（见下方 规则）
```

**来源标注与评估过滤（A1）**：11 例案例**全部拆解提炼**入库（非原文整段），是知识单元的"源头来源"；知识库另有一部分为 AI 生成、经疗愈师初步验证。因此 `source_ref` 必须可机读过滤：

- 源自案例库：`case-XXX`（精确到案例编号，对应 knowledge/healing/cases/索引.md）
- AI 生成经疗愈师验证：`ai-generated · healer-validated`
- 上游体系文档：文档路径

**评估检索按来源过滤**（EVAL-SUITE §二 A1）：考 case-X 的曼陀罗时，RAG 检索范围**排除**所有 `source: case-X` 的知识单元（提炼 ≠ 原文，泄漏间接但存在，此规则将其限制在知识点级可过滤）；考基准测试集/新增画作时不排除。案例 ≥20 例后切换建库/考试分集，届时修订 EVAL-SUITE。

### 3.3 知识状态分级

| 状态 | 含义 | 使用边界 |
|---|---|---|
| `ai_draft` | AI 生成草稿，未验证 | 仅内部候选，不得进入对外输出 |
| `source_supported_draft` | 有来源支撑的初版 | 可内部测试 |
| `case_verified` | 已通过案例验证 | 可用于报告生成 |
| `reviewed` | 人工审核通过 | 可用于正式用户输出 |

**维护权限模型**：知识库为平台资产，开发者（平台方）为**唯一维护者**；疗愈师为使用者（只读，经 Agent 检索调用），不开放直接编辑权。设计理由：知识库构建与维护（本体对齐、来源验证、状态分级）专业门槛高，个体疗愈师不具备维护能力，由平台统一提供质量有保障的知识库。三层边界：

- **平台知识库**（本文件描述的知识单元 / 案例库 / 本体论）：开发者写、疗愈师只读
- **疗愈师个人工作区**（个案档案、报告记录、个人笔记、话术偏好）：本地私有（单用户本地形态，D-106），疗愈师自由编辑，**不进共享知识库，也不进入报告生成的知识供给**
- **反馈通道**（零门槛）：疗愈师以自然语言反馈"解读不准 / 未覆盖 / 超纲"→ 缺口队列（行为层，带审计）→ 开发者审核 → 质量流程入库（知识治理闭环）

**演进方向（未来版本，非 MVP）**：疗愈师个人知识库——**Agent 自动记忆系统**，不由疗愈师手动维护：疗愈师对报告的修改被自动沉淀为个人记忆，后续解读时将个人记忆用于优化针对该疗愈师的个性化报告生成。MVP 阶段个人记忆不参与生成。

知识状态升级路径（`ai_draft` → `reviewed`）的**审核决策权归属开发者**；Agent 只收集不写入（人工决策门槛延续）。

### 3.4 转述风险分级

- `relay_risk: low`：可直接被来访者读到，无需转译
  - 通俗解释、常见表现、温和反思、基础调理建议
- `relay_risk: medium/high`：面向疗愈师的专业内容；应答准备场景引用时需附口径提醒或降级表达
  - 专业诊断术语、深层创伤内容、复杂病理分析、具体技术细节

**可见性判断原则**：
- 可能引起来访者过度焦虑或自我解读的 → 转述时附"可能性"口径
- 需要专业背景才能正确理解的 → 不可见
- 能帮助来访者理解自己、但不会造成困扰的 → 可直接转述
- 基础的自我觉察和轻量练习 → 可见

## 四、检索层设计

### 4.1 三路召回策略

| 召回方式 | 作用 | 适用场景 | 权重（MVP） |
|---|---|---|---|
| 结构化召回 | 按状态 ID、议题、类型精确检索 | 明确知道要找什么状态/议题 | 50% |
| 向量召回 | 语义相似度匹配 | 模糊查询、自然语言问题 | 30% |
| 关键词召回 | 精确关键词匹配 | 专业术语、特定概念 | 20% |

### 4.2 两场景检索差异

| 维度 | 解读参谋场景 | 应答准备场景 |
|---|---|---|
| 知识范围 | 全部知识单元 | 全部知识单元 |
| 内容偏好 | 优先专业版内容 | 专业版 + 通俗解释字段（可转述） |
| 检索深度 | 根因层 + 核心层 + 表现层 | 核心层 + 表现层（根因层附"可能性"口径） |
| 召回数量 | 多（深度分析） | 少而精（聚焦来访者问题） |
| 风险过滤 | 仅过滤 forbidden | 过滤 forbidden；caution 级按转述口径降级表达 |

### 4.3 检索流程

```
用户问题
  → 问题分类（细节追问/深度探讨/视角切换/方案细化/跨议题关联）
  → 报告定位（从报告中提取相关段落和状态）
  → 本体论关联（通过状态 ID 找到关联状态和关系）
  → 三路召回（结构化 + 向量 + 关键词）
  → 结果融合（按权重排序，去重）
  → 模式过滤（按可见性规则过滤）
  → 返回检索结果（带置信度评分）
```

## 五、推理层设计

### 5.1 三类核心推理

#### 类型一：状态因果链推理

- 数据源：**状态.md §三 因果图谱**（知识库关系图谱）
- 基于 leads_to / underlies 关系
- 从表现层状态追溯到核心层和根因层
- **使用边界**：图谱只提供候选提示，每个候选必须回到画面找证据——画面上有对应信号才确认，无证据不落笔（与状态.md §3.1 使用边界一致）
- 输出：完整因果链条 + 每一步的置信度 + 画面证据引用

#### 类型二：五行乘侮推理

- 数据源：五行解读.md
- 基于五行生克乘侮关系
- 从一个宫位的失衡推断对其他宫位的影响
- 输出：乘侮路径 + 调理原则（抑强扶弱）

#### 类型三：跨议题关联推理

- 基于状态共享和五行生克，找到议题之间的关联
- 从主议题延伸到关联议题
- 输出：关联路径 + 关联强度 + 探索建议

#### 类型四：组合模式综合判断

- 数据源：组合模式.md
- 多个画面信号共同出现时，若命中组合模式库，作高阶综合判断（信号组整体含义）
- **使用边界**：不替代基础规则；未命中回基础层逐信号推理；已审核组合模式可进报告候选，仍需结合画面事实、圈层和主题
- 输出：命中的组合模式 + 综合判断结论 + 来源等级（manual_supported_draft / reviewed_case_rule）

### 5.2 推理置信度

| 等级 | 含义 | 输出方式 |
|---|---|---|
| 高（>80%） | 有明确本体论依据 + 多案例验证 | 直接陈述 |
| 中（50-80%） | 有理论依据但案例较少 | "可能""往往" |
| 低（<50%） | 理论推导，待验证 | "有一种可能性是""仅供参考" |

### 5.3 两场景推理差异

- **解读参谋场景**：完整推理链条 + 专业术语 + 多视角分析
- **应答准备场景**：结论层 + 通俗解释 + 依据指向（报告哪一章）；弱化不确定内容；不给出来源之外的深层结论

## 六、生成层设计

### 6.1 两阶段生成

```
检索结果 + 推理结果
  → 硬结论规则引擎（确定性内容）
    → 状态判定、五行分析、调理方向等有明确规则的内容
  → 软表达大模型（自然语言组织）
    → 把硬结论用自然语言组织成流畅的回答
    → 按模式调整语言风格和深度
  → 输出最终回答
```

### 6.2 报告生成流程

```
画面特征提取
  → 信号→状态映射
  → 组合模式综合判断（可选：多信号命中组合模式库时启用，未命中跳过）
  → 本体论关联推理（因果链 + 五行 + 跨议题；因果链用 状态.md §三）
  → 知识库补充（议题详情 + 疗愈方案）
  → 按报告模板组织内容
  → 生成结构化报告
  → 质量检查（一致性 + 安全性）
  → 输出报告
```

### 6.3 问答生成流程

```
用户问题 + 报告上下文
  → 问题分类
  → 报告定位 + 知识库检索
  → 推理（如需）
  → Prompt 工程（模式适配 + 约束注入）
  → 大模型生成
  → 输出安全审核
  → 输出回答 + 来源标注 + 边界提示
```

### 6.4 Prompt 工程要点

**通用约束**：
- 锚定报告：回答必须基于报告内容，不凭空捏造
- 边界清晰：超出范围明确说明
- 来源标注：关键结论标注依据

**解读参谋场景**：
- 专业精准，使用专业术语
- 多视角分析，逻辑清晰
- 提供可操作的建议

**应答准备场景**：
- 专业 + 可转述：专业判断 + 通俗解释并列
- 有温度，不评判
- 给可能性不给定论；附"能量层面参考，不是诊断"口径提醒

## 七、上下文管理

### 7.1 三层记忆

| 记忆层级 | 内容 | 存储方式 | 生命周期 |
|---|---|---|---|
| 短期记忆 | 当前对话历史 | 上下文窗口 | 单次对话 |
| 中期记忆 | 当前报告完整内容 + 摘要 + 定稿图与标记参数 | 结构化存储 | 报告生命周期 |
| 长期记忆 | 个案档案、历史报告、问答记录 | 向量数据库 + 结构化索引 | 长期 |


### 7.2 报告锚定策略

问答全程锚定原始报告，防止跑偏：
- 使用报告核心元数据（report_id、core_states、main_topics）作为锚点
- 每轮对话注入报告摘要，确保上下文一致
- 回答必须引用报告中的具体段落或结论

### 7.3 上下文溢出处理

当对话轮次增多、上下文可能溢出时：
- **分层摘要**：对历史对话做滚动摘要，保留关键信息
- **报告优先**：报告内容始终在上下文中，对话历史可摘要
- **关键状态常驻**：核心状态列表始终保留在上下文中

### 7.4 Token 成本估算（MVP）

- 报告上下文（摘要 + 关键段落）：~3k tokens
- 系统提示词（模式配置 + 安全约束）：~1k tokens
- 对话历史（最近 5 轮）：~2k tokens
- 检索结果（3-5 个知识单元）：~2k tokens
- 用户输入 + 模型输出：~1-2k tokens
- **单次问答总计**：约 9-11k tokens

## 八、安全护栏

### 8.1 四级内容分级

| 级别 | 含义 | 应答准备场景处理（输出可能被转述给来访者） |
|---|---|---|
| safe | 安全内容，无风险 | 正常输出 |
| reminder | 需要提醒的内容（如"每个人情况不同"） | 输出 + 提醒语 |
| caution | 谨慎内容，可能引起不适或误解 | 降级输出（更温和、更模糊） |
| forbidden | 禁止内容（医学诊断、承诺、危机等） | 拦截 + 引导语 |

### 8.2 输入安全检测

| 检测类型 | 触发条件 | 处理方式 |
|---|---|---|
| 危机信号 | 自伤、自杀、严重自残倾向 | 触发危机干预话术，提供求助资源 |
| 严重心理问题 | 重度抑郁、精神病性症状等 | 建议就医，不做解读 |
| 医学问题 | 具体疾病诊断、用药咨询 | 建议咨询医生 |
| 法律/财务问题 | 具体法律建议、投资建议 | 建议咨询专业人士 |
| 恶意提问 | 攻击、试探边界、违法内容 | 礼貌拒绝 |

### 8.3 输出安全审核

| 审核类型 | 检查内容 | 处理方式 |
|---|---|---|
| 诊断类 | "你有 XX 病""这是 XX 症" | 改为可能性描述："可能表现为""有 XX 的倾向" |
| 承诺类 | "一定会好""肯定有效" | 改为："可能有帮助""对很多人有效" |
| 绝对化 | "所有""全部""永远""必须" | 改为："可能""往往""很多时候" |
| 超范围 | 回答内容超出报告范围 | 标注："这是延伸探讨，不是报告结论" |
| 评判性 | "你这是不对的""你应该" | 改为接纳性表达："有这种感受很正常" |
| 重大决策引导 | 引导分手、辞职、投资等 | 删除引导，保持中立 |

### 8.4 免责声明策略

- **敏感话题口径提醒**（两场景，应答准备强制）：涉及心理/健康等敏感话题时，回答附"能量层面参考，不是诊断；建议结合来访者实际情况，必要时寻求专业帮助"
- **报告末尾声明**：每份报告末尾有标准免责声明
- **敏感话题追加声明**：涉及心理、健康等敏感话题时，重复提醒

### 8.5 安全审核流水线

```
生成内容
  → 规则检测（关键词 + 模式匹配）
  → 分类器检测（安全分类模型）
  → 不通过 → 重生成（带约束）或降级输出
  → 通过 → 输出
```

## 九、评估体系

### 9.1 黄金测试集

基于 11 个人工解读案例构建：
- 输入：曼陀罗画 + 用户信息
- 期望输出：人工解读报告（作为参考答案）
- 用途：评估报告生成质量和准确性

### 9.2 评估维度

| 维度 | 指标 | MVP 目标 |
|---|---|---|
| 检索质量 | 召回率、准确率 | 召回率 > 85% |
| 生成质量 | 与人工解读一致性 | > 80% |
| 问答质量 | 锚定率、相关性 | 锚定率 > 90% |
| 安全性 | 越界内容数量 | 0 条严重越界 |
| 场景适配 | 两场景区分度 | 解读参谋深度、应答准备可转述性各自达标 |
| 用户满意度 | 主观评分 | 疗愈师 ≥ 3.5 分（1-5 分制，口径 M-070） |

### 9.3 Bad Case 处理流程

1. 收集 Bad Case（用户反馈 + 自动检测）
2. 分类归因（检索问题 / 推理问题 / 生成问题 / 安全问题）
3. 定位根因（知识库 / 算法 / Prompt / 数据）
4. 修复并回归测试
5. 加入测试集防止复发

## 十、MVP 实施方案

### 10.1 简化策略

MVP 阶段不追求完美，优先跑通闭环：

- 知识结构化：**13 个议题节点（8 外圈议题 + 4 中圈方向 + 1 内圈核心）各建最小知识单元**；财富议题内容最厚，其余议题先保"最小可用"（每议题：核心状态链 + 典型失衡模式 + 基础调理方向），深度后补
- 检索系统：结构化路由（按稳定 ID 精确查）+ 关键词召回（中文 2-gram + 整词匹配打分取 Top-K）；向量召回留作 L3 升级位，知识库规模到位再引入（本期不实现）
- 推理系统：状态因果链推理优先实现，五行乘侮和跨议题关联简化
- 生成系统：Prompt 工程为主，硬结论规则引擎 MVP 阶段可不单独实现
- 安全护栏：规则检测 + 关键词匹配为主，分类器后补
- 评估系统：人工评估为主，自动化评估后补

### 10.2 实施步骤

**第一步：知识结构化**
- 整理财富议题核心状态（已完成大部分）
- 其余 12 个议题节点补最小知识单元（每议题最小集：核心状态链 + 典型失衡模式 + 基础调理方向）
- 按知识单元格式结构化
- 建立状态 ID 体系与本体论对齐

**第二步：检索系统搭建**
- 结构化索引（稳定 ID 精确路由）
- 关键词检索 pipeline（中文 2-gram + 整词匹配打分取 Top-K）
- 向量数据库：不建，留作 L3 升级位

**第三步：生成与问答**
- 报告生成 Prompt 模板
- 问答 Prompt 模板（两场景）
- 基础安全护栏

**第四步：评估与迭代**
- 黄金测试集评估
- Bad Case 收集与修复
- 迭代优化
